# Decision Log — meeg-blog

Project decisions preserved for AI agents. Each entry is dated.

---

## 2026-06-15

### /explore decisions

- **Replatform to Dato CMS + Cloudflare.** Moving from Storyblok + Render to cut costs and simplify. Dato on Free plan, Cloudflare for near-zero hosting.
- **Cloudflare analytics over Plausible.** Built-in, free, good enough. No need for a paid analytics service.
- **Sentry dropped.** No error-tracking need identified for a personal blog. One less service to manage.
- **Design must be unique (no templates).** Acknowledged as a risk given no design background.

### /design decisions

- **SSR on Cloudflare Workers.** Chose `output: 'server'` with `@astrojs/cloudflare`. Content fetched from Dato on each request. Dato CDN caching keeps it fast. Rejected static rebuild (user chose freshness).
- **Astro 6 confirmed.** No Cloudflare compatibility issues found with `@astrojs/cloudflare`. Keeping Astro.
- **Dato CMS Free plan sufficient.** 300 records, 100k API calls/month. ~72 records projected. Acceptable.
- **Dato Structured Text for rich content.** Rejected Markdown. Structured data enables reliable code block, image, and embedded content rendering with no custom parsing.
- **CSS custom properties + Open Design AI.** Design tokens from Open Design AI's DESIGN.md map to CSS custom properties. Rejected Tailwind (token adapter friction), CSS Modules from scratch (no design system foundation), and pre-built templates.
- **Vanilla JS for theme toggle, no Preact.** One interactive element doesn't warrant a framework bundle. Reused the old theme-switch concept but dropped the Preact dependency.
- **Cloudflare Web Analytics.** Free, built-in, privacy-friendly, zero config.
- **Dato API caching.** Worker sets `Cache-Control` headers so Cloudflare edge caches rendered HTML. Stays within 100k API calls/month.
- **`jose` for JWT signing over `jsonwebtoken`.** `jose` uses Web Crypto API (`crypto.subtle`) natively available in the Workers runtime. `jsonwebtoken` depends on Node.js `crypto`/`Buffer` with limited Workers compatibility.
- **`wrangler.jsonc` with `compatibility_date` and `observability`.** Explicit wrangler config generated by `@astrojs/cloudflare`. `compatibility_date` set to project start date, `observability` enabled for Worker log visibility. No `nodejs_compat` flag needed since `jose` uses native Web Crypto.
- **`.env` for local secrets, `wrangler secret put` for prod.** Astro + wrangler both pick up `.env` natively in dev. Production secrets set via `wrangler secret put` or Cloudflare dashboard — never committed to source.

## 2026-06-16

### /plan decisions

- **11 stories derived from SPEC.md.** Split STORY-001 (foundation) from STORY-003 (content pages) at user's request. Added STORY-002 for content migration from Storyblok — recognised as a distinct prerequisite between foundation and content pages.
- **Content migration (STORY-002) is a hard sequencing gate.** Blog listing (T013) and article page (T014) depend on migrated content existing in Dato — pages are meaningless without data. Foundation (STORY-001) must complete before migration can begin.
- **Visual Editing (STORY-011) included in initial scope, not deferred.** All Visual Editing tasks gated at the end of the plan since they depend on content pages, layout, and SEO all existing.
- **No Cloudflare deployment until after development.** User prefers to validate locally via `wrangler dev` / `astro dev`. No domain configuration needed for development.
- **Dato CMS account does not yet exist** — T002 (setup-dato-schema) includes creating the account. This is a blocker for T003 (CDA client needs tokens) and T006 (migration needs schema).
- **39 tasks across 11 stories**, sequenced with explicit `depends-on` and `parallel-group` tags. First parallel group: T003 (CDA client) and T004 (design tokens) can run concurrently after T001 (scaffold).
- **Wire tasks required for every route.** Every story that adds a production entry point has a terminal `wire-*` task whose acceptance is a real request through the built binary.

### /plan second pass

- **Monorepo adopted.** `pnpm-workspace.yaml` now defines `apps/*` and `packages/*`. The blog app lives in `apps/blog/`, the throw-away migration tool in `packages/storyblok-migration/`. This isolates the migration script from the production app.
- **`@datocms/cma-client-node` added** as a dependency for the throw-away migration script in `packages/storyblok-migration/`. Not part of the production app's dependency tree.
- **Content migration re-sliced to four tasks.** T006–T007 (old) → T008–T011 (new): Pull Storyblok data via CLI, write migration tool, run migration, verify. Recognised that rich text transformation (Storyblok → Dato Structured Text) is the riskiest part; complex transforms are flagged for resolution when identified.
- **STORY-001 expanded** with two new ACs for monorepo structure and migration package scaffold. Original ACs shifted (AC3→AC5, AC4→AC6, etc.).
- **43 tasks** (was 39), renumbered T001–T043 to accommodate finer migration slice. First parallel group A: T001 (root workspace), T002 (blog app), T003 (migration package) can all run concurrently.
- **Spec files to be regenerated** — previous shim specs invalidated by story/plan changes.
